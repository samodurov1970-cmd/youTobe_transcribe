## 📋 План на завтра: Логирование и тесты

### Цель
Добавить единообразное логирование по всему коду `youtube_transcribe` и написать тест для классификации тем каналов через LLM.

---

### Этап 1: Стандартизация логирования (1.5–2 ч)

**Формат логов:**
```
[COMPONENT]: Жирное описание проблемы на русском → ключ:значение
```

Примеры:
```
CHANNELS: Не удалось получить список подписок → error: "dial tcp: connection refused", count: 0
WORKFLOW: Видео уже обработано → video_id: "abc123", status: "skipped"
LLM: Ошибка классификации темы канала → channel_id: "UC123", error: "ollama returned unrecognized topic"
```

**Изменить нужно в файлах:**
| Файл | Методы для логирования |
|------|----------------------|
| `internal/channels/channels.go` | `processOnce`, `saveSubscriptions`, `fetchSubscriptions`, `markUnsubscribed` |
| `internal/channels/classify.go` | `classifyChannel`, `classifyChannelWithLLM` |
| `internal/channels/llm.go` | `Classify` (уже есть, добавить `request_start`) |
| `internal/channels/notify.go` | `notifyNewSubscriptions`, `notifyUnsubscriptions` |
| `internal/channels/telegram.go` | `SendMessage`, `SendPhoto` |
| `internal/workflow/workflow.go` | `Run`, `processVideo`, `transcribeVideo` |
| `internal/transcribe/transcribe.go` | `Transcribe` |
| `internal/storage/claims.go` | `Claim`, `Release` |
| `internal/obsidian/obsidian.go` | `WriteNote`, `Sync` |
| `cmd/transcribe/main.go` | `main`, `signalHandler` |

**Действия:**
1. Создать вспомогательный пакет/файл `internal/logger/logging.go` с функциями:
   ```go
   func ComponentLog(component string) *slog.Logger
   // или
   func FormatLog(component, message string, args ...any)
   ```
2. Обновить `internal/logger/logger.go` с новыми форматами
3. Применить логи во всех методах
4. Добавить правило в `CLAUDE.md`

---

### Этап 2: Тест классификации LLM (30–40 мин)

**Файл:** `internal/channels/llm_classify_test.go`

**Что тестировать:**
- ✅ `parseTopic` — извлечение 1/2/3 из ответа Ollama
- ✅ `buildPrompt` — корректность составления промпта
- ✅ `Classify` — mock HTTP-сервер, проверка парсинга ответа
- ✅ `classifyChannelWithLLM` — fallback на keyword-based классификатор при ошибке LLM

**Инструменты:**
- `net/http/httptest` для mock-сервера Ollama
- Стандартные `testing` + `assert`

---

### Этап 3: Проверка в ELK (10 мин)

1. Пересобрать и перезапустить:
   ```bash
   docker compose up -d --build
   ```
2. Проверить логи в Kibana:
   ```
   http://localhost:5601 → Discover → youtube-transcribe-*
   ```
3. Убедиться, что все логи попадают в ELK с новым форматом
