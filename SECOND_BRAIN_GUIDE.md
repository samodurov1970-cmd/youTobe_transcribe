# «Второй мозг» для трейдинга — руководство по построению

Проект `youTobe_transcribe` — это набор микросервисов на Go для отслеживания YouTube-каналов, скачивания аудио, транскрибации через Whisper и сохранения в Obsidian. Это руководство описывает, как на базе этого проекта построить **базу знаний («второй мозг») для трейдинга**: векторное хранилище чанков транскрипций, конвейер индексации, ретрив-конвейер поиска и генерацию ответов с ссылками на источники.

## Архитектура системы

```
YouTube-каналы (трейдинг) → channels → videos → video_files (транскрипты Whisper)
                                                  │
                                                  ▼
                                          chunk_and_embed.py
                                          (разбивка на чанки,
                                           эмбеддинги, pgvector)
                                                  │
                                                  ▼
                                     public.knowledge_chunks
                                                  │
                                                  ▼
                              retrieve_and_answer.py
                              (векторный поиск + диверсификация +
                               дедупликация + ответ в 3 раздела)
                                                  │
                                                  ▼
                                     ОТВЕТ ПО ТРЕЙДИНГУ
                                     со ссылками video_id + chunk_index
```

## Стек технологий

| Компонент | Технология |
|-----------|-----------|
| Язык скриптов | Python 3.11 |
| База данных | PostgreSQL 15 + расширение `pgvector` |
| Эмбеддинги | Jina AI / Cohere / Gemini (онлайн) или `sentence-transformers` (CPU fallback) |
| Ранжирование | pgvector cosine similarity (опционально reranker) |
| Хранилище заметок | Obsidian (Markdown) |
| Автоматизация | n8n, cron / ночные батчи |
| Нотификации | Telegram Bot API |

## Этап 0. Подготовка базы (один раз)

**Цель:** создать таблицы под хранение чанков с зафиксированной размерностью вектора и полем для отслеживания ошибок.

### 0.1. Установить pgvector

В контейнере PostgreSQL:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

### 0.2. Выбрать модель эмбеддингов и зафиксировать размерность

`pgvector` требует конкретное число: `vector(768)`, `vector(1024)`, `vector(1536)` и т.д.

| Модель | Размерность | Языки |
|--------|------------|-------|
| BGE-M3 | 1024 | ru + en |
| EmbeddingGemma | 768 | mu |
| multilingual-e5-small | 384 | ru + en |
| multilingual-e5-base | 768 | ru + en |
| paraphrase-multilingual-MiniLM-L12-v2 (CPU fallback) | 384 | ru + en |
| Jina v3 | 1024 | mu |

**Рекомендация:** для русскоязычного трейдинга выберите `multilingual-e5-base` (768) или `BGE-M3` (1024). Размерность фиксируется один раз — при смене модели придётся пересоздавать таблицу и пересчитывать все векторы.

### 0.3. Создать таблицы

Выполните SQL из файлов:
- `sql/001_knowledge_chunks.sql`
- `sql/002_indexing_jobs.sql`

### 0.4. Создать индексы

```sql
-- Векторный индекс для семантического поиска
CREATE INDEX idx_knowledge_chunks_embedding ON public.knowledge_chunks
USING ivfflat (embedding vector_cosine_ops)
WITH (lists = 100);

-- Полнотекстовый индекс для точного поиска тикеров, стратегий, брокеров
CREATE INDEX idx_knowledge_chunks_text ON public.knowledge_chunks
USING gin (to_tsvector('russian', chunk_text));

-- Индекс по видео для быстрой фильтрации
CREATE INDEX idx_knowledge_chunks_video_id ON public.knowledge_chunks(video_id);

## Этап 1. Пилот: индексация первых 14 видео

**Цель:** отладить конвейер на малом объёме, прежде чем браться за 3272 видео.

1. Возьмите 14 записей из `public.video_files`, где `validation_status = 'published'`.
2. Для каждой транскрибации:
   - отметьте чанки рекламы флагом `is_ad = true` (промокоды, «спонсор», «ссылка в описании», «discord», «выгодно и надежно»), но не удаляйте из базы,
   - разбейте текст на чанки размером 300–500 токенов (≈1500–3000 символов для русского),
   - overlap 15–20% между соседними чанками,
   - режьте только по границам предложений,
   - определите язык каждого чанка (`ru` / `en`),
   - присвойте `chunk_index`,
   - проверьте, существует ли `video_id` в `public.videos`; если нет — поставьте `is_orphan = true`.
3. Посчитайте эмбеддинги через выбранный онлайн-API. Если онлайн-API не работает — используйте fallback: локальный CPU-эмбеддинг через `sentence-transformers` с моделью `paraphrase-multilingual-MiniLM-L12-v2`.
4. Запишите чанки с векторами в `public.knowledge_chunks`, отметьте в `indexing_jobs`, что эти 14 видео обработаны.

**Критерий готовности:** 14 видео индексированы, чанки с векторами, языком, флагами `is_ad` и `is_orphan` находятся в `knowledge_chunks`.

-- Индекс по каналу для диверсификации
CREATE INDEX idx_knowledge_chunks_channel ON public.knowledge_chunks(channel_name);
```

**Критерий готовности:** в базе есть пустые таблицы `knowledge_chunks` и `indexing_jobs` с фиксированной размерностью вектора.

## Этап 2. Выбор и проверка эмбеддинг-провайдера

**Цель:** зафиксировать способ вычисления векторов для оставшихся 3258+ видео.

1. Попробуйте зарегистрироваться у провайдера с бесплатными эмбеддингами (Jina AI, Cohere, Gemini Embedding и т.д.). Проверьте:
   - требуется ли банковская карта при регистрации,
   - какой бесплатный лимит на запросы в месяц,
   - хватит ли его на 32k+ чанков (примерно 3272 видео × 10–15 чанков).
2. Если бесплатного онлайн-API хватает — используйте его. Если нет (или требуется карта) — **фallback на локальный CPU**: `sentence-transformers` с моделью `paraphrase-multilingual-MiniLM-L12-v2`. На слабом ПК это займёт больше времени, но без лимитов и без карт.
3. Reranker: без reranker система работает, но качество ответов на сложные вопросы (сравнение стратегий, агрегация мнений) будет заметно ниже. Начинать можно без reranker, но если качество не устроит — добавляйте reranker (даже локальный cross-encoder на CPU).

**Критерий готовности:** вы знаете, каким именно способом будете считать эмбеддинги, и у вас есть ключи (если нужны).

## Этап 3. Первичная индексация оставшихся 3258 видео (очередь с чекпоинтами)

**Цель:** проиндексировать всё видео из `public.videos`, которое ещё не попало в `public.video_files` с текстом, плюс новые, которые будут добавляться.

1. Как только новая транскрибация появляется в `public.video_files` со статусом `published`:
   - добавьте её в `indexing_jobs` со статусом `queued`,
   - скрипт берёт видео из очереди батчами (например, по 10–20 штук),
   - режет на чанки (с фильтром рекламы, языком, overlap, проверкой `is_orphan`),
   - считает эмбеддинги (онлайн или fallback CPU),
   - пишет в `knowledge_chunks`,
   - помечает в `indexing_jobs` как `done` или `failed` (с `error_message`, если не удалось).
2. Запускайте индексацию ночью батчами. На 3272 видео это может занять несколько ночей — это нормально. Главное — не торопиться и не терять чекпоинты. Если скрипт упадёт, вы продолжаете с последнего `done` в `indexing_jobs`.
3. Одновременно можно индексировать одобренные записи из `public.pending_review` (где `status = 'approved'`), если в них есть полезный текст.

**Критерий готовности:** все видео, которые есть в `public.video_files` со статусом `published`, имеют свои чанки с векторами в `knowledge_chunks`. Очередь `indexing_jobs` пустая или содержит только текущие задачи.

## Этап 4. Настройка retrieval pipeline (поиск при вопросе)

**Цель:** когда вы задаёте вопрос, система находит релевантные чанки по всей базе.

**Вариант Б (скрипт-посредник) — основной путь.** Большинство бесплатных моделей в VS Code не умеют вызывать произвольные SQL-инструменты. Вам нужен скрипт (Python/Go, примерно 100–200 строк), который:

1. Получает вопрос от вас.
2. Считает эмбеддинг вопроса через то же API, что и чанки.
3. Ищет 30–50 кандидатов в `knowledge_chunks` через векторный поиск `pgvector` + фильтр `is_ad = false` + фильтр `lang` + опционально `tsvector` для точных терминов.
4. **Исключает из выдачи чанки с `is_orphan = true`** (или хотя бы логирует их наличие), чтобы в ответ не попали чанки без метаданных канала.
5. Применяет диверсификацию по каналу: не больше 2–3 чанков с одного канала (`ROW_NUMBER() OVER (PARTITION BY channel ORDER BY score DESC)`). Это предотвращает ответ от «мнения 2–3 каналов».
6. Применяет дедупликацию по эмбеддингам (порог 0.92) — убирает почти идентичные чанки.
7. Берет топ-10–15 чанков после всех фильтров.

## Этап 5. Генерация ответа (структура в 3 раздела)

Когда модель получает чанки, она должна сформировать ответ:

1. **Раздел 1: Согласно вашей базе** — обобщение найденных фрагментов с ссылками на источники `(video_id + chunk_index)`, без перенаправления «посмотрите видео сами».
2. **Раздел 2: Что я думаю согласно моим базам** — мои добавления, уточнения, нюансы, чётко отделены.
3. **Раздел 3: Итоговый вывод — как действовать** — готовая пошаговая инструкция, смесь первого и второго.

**Требования:**
- Каждое утверждение в разделе 1 — ссылка `video_id + chunk_index`. Если не можете подкрепить ссылкой — не пишите утверждение.
- Нет рекламы.
- Каналы диверсифицированы (не больше 2–3 чанков с одного канала).

## Этап 6. Тестовый вопрос и проверка качества

1. Задайте модели вопрос по теме торговли (например, «как начать торговать на рынке?»).
2. Проверьте ответ по трём разделам (см. Этап 5).
3. Проверьте, что ответ не доминируется одним каналом.
4. Проверьте, что в ответе нет рекламных фрагментов.
5. Проверьте, что дедупликация сработала — нет одинаковых тезисов из разных видео подряд.

**Критерий готовности:** ответ высокого качества, готов к эксплуатации.

## Этап 7. Ежедневная инкрементальная индексация

**Цель:** новые видео (+20/день) попадают в базу знаний автоматически.

1. Когда ваша программа транскрибирует новое видео и запись попадает в `public.video_files`:
   - скрипт обнаруживает новый `video_id`,
   - добавляет задачу в `indexing_jobs`,
   - в следующем ночном батче режет на чанки, считает эмбеддинги, пишет в `knowledge_chunks`.
2. Старые видео не пересчитываются, если их текст не изменился.

**Критерий готовности:** новые транскрибации появляются в базе знаний в течение суток после публикации в `video_files`.

## Этап 8. Мониторинг и контроль качества (постоянно)

Регулярно проверяйте:
- попадают ли в топ релевантные чанки, или система тянет не по теме,
- не доминируют ли 2–3 канала,
- не просочилась ли реклама в чанки (обновите эвристики `is_ad`),
- не обрываются ли мысли на границах чанков (если да — увеличьте размер или overlap),
- не выдумывает ли модель факты в разделе 1 (сверить ссылки `video_id + chunk_index` с реальными чанками),
- не накопилось ли слишком много дублей (проверьте порог дедупликации 0.92),
- есть ли новые `is_orphan` чанки (либо исключайте их из выдачи, либо логируйте для анализа).

## 10 ВАЖНЫХ ПРИНЦИПОВ (не нарушать)

1. **Вычитывать все 3272 сейчас, не ограничивать, ответ может быть скрыт в любом видео.** Лучше медленнее, чем некачественно.
2. **Индексация идёт очередью с чекпоинтами (`indexing_jobs`)**, батчами, по ночам. Если скрипт упадёт — продолжаем с последнего успешного видео.
3. **Реклама фильтруется на уровне чанков (`is_ad = true`)**, а не удаляется из сырого текста.
4. **Диверсификация по каналу: не больше 2–3 чанков с одного канала в финальной выдаче.**
5. **Защита от галлюцинаций: каждое утверждение в разделе 1 — ссылка `video_id + chunk_index`.**
6. **Мультиязычные эмбеддинги только (русский + английский вперемешку).**
7. **Размерность вектора фиксируется один раз при создании таблицы.**
8. **Дедупликация по эмбеддингам (порог 0.92) применяется после диверсификации по каналу, перед финальным топом.**
9. **Чанки с `is_orphan = true` исключаются из выдачи или логируются.**
10. **Слабый ПК — всё тяжёлое вычисление онлайн-API или локальный CPU fallback, без установки тяжёлых библиотек на ваш ПК.**

## Быстрый старт

```bash
# 1. Поднять базу с pgvector
docker compose up -d postgres

# 2. Создать таблицы
psql -U peter -d youtube_tracker -f sql/001_knowledge_chunks.sql
psql -U peter -d youtube_tracker -f sql/002_indexing_jobs.sql

# 3. Установить Python-зависимости
pip install sentence-transformers psycopg2-binary numpy pyyaml

# 4. Запустить пилот на 14 видео
python scripts/chunk_and_embed.py --mode pilot --limit 14

# 5. Проиндексировать всё remaining
python scripts/chunk_and_embed.py --mode full

# 6. Задать вопрос
python scripts/retrieve_and_answer.py --question "как начать торговать на рынке?"

# 7. Ежедневная инкрементальная индексация (добавить в cron)
python scripts/ingest_daily.py
```
